## Summary
Using CRT on an app today means adding a line (and usually a dependency and a CSP exception) to the app, or browsing a proxied copy on another port. Add a third way that needs nothing from the app: `crt browse` starts Chrome or Edge itself with a per-project profile and a DevTools-protocol pipe, registers the existing loader to run in every new document of every tab before the page's own scripts, and switches CSP enforcement off for tabs on a loopback host. The page is then in embedded mode on the app's own URL exactly as if the app had included the loader. This milestone adds the browser module, the loader change that injection needs, the `crt browse` command and the browser's lifecycle; it does not change what plain `crt` opens (that is M32, CRT-0053).

## Context
- The loader is `packages/overlay/src/loader.ts` (`mountCrt` → `mount`): it installs the console/network hooks, resolves the CRT origin (option, else the script tag's own origin, else `http://localhost:4400`), and `append()` adds `<script src="<origin>/__crt/overlay.js" defer>` to `document.head ?? document.documentElement`. Injected at document creation there is no root element yet: `appendChild` throws on null, and because `script` was assigned before the throw, `retry()` returns early for ever. `loader-auto.ts` is the IIFE entry served at `/__crt/loader.js`; it reads `data-crt-port` off its own tag, which an injected script does not have. `packages/overlay/build.mjs` builds both forms.
- The server opens the default browser with `openBrowser` in `packages/server/src/serve.ts` (a platform opener spawned with `shell: false`; `CRT_BROWSER` is its test seam). That stays for the integration case.
- `/__crt/internal/*` routes refuse any request carrying an `Origin` header (`proxy.ts`; the shutdown route is the model). Route paths are constants in `routes.ts`.
- Embedded-mode CORS already allows every loopback origin, so an injected overlay needs no server change to talk to `/__crt/*`.
- Prototype, 2026-11-16, against the 0.7.2 build (PRD-zero §5.1): an untouched app under `default-src 'self'; script-src 'self'; style-src 'self'; connect-src 'self'; img-src 'self'; frame-src 'none'`; the loader passed to `Page.addScriptToEvaluateOnNewDocument` behind a `MutationObserver` that waits for the root element, plus `Page.setBypassCSP`. The overlay loaded, the app's first-script `console.error` was captured, a stub Send completed, and the overlay returned after a navigation. Without the bypass the overlay script was refused by `script-src 'self'`. The prototype used Playwright's protocol session, not the pipe, and headless Chromium on Linux, not real Chrome or Edge on Windows.

## Notes
Read `docs/PRD-zero.md` §5.1, §6.1, §7 (N-31, N-32), §11 and §12 first. Decisions already taken (§13): a launched browser, not an extension; the debugging pipe and a per-project profile, never a debug port (§12 rule 2: if the pipe does not work somewhere, stop and report — do not fall back to a port); never `--enable-automation` or `--disable-web-security` (§12 rule 4). The pipe on Windows is the part the prototype did not cover: Node passes extra stdio handles to a child on Windows and Puppeteer's `pipe: true` relies on the same thing, but verify it first, before building the rest. Chrome is believed to ignore remote debugging on the default profile since Chrome 136, which is why the profile is dedicated; confirm against the installed version and record it. M28 is independent of M29; plain `crt` keeps opening the default browser until M32.
