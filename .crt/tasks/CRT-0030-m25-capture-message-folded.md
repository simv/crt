## Summary
After **Send**, the popover's first bubble is the whole F-24 first message as the agent receives it — `CRT intake for capture …`, the bundle path, page, framework, console and network lines, every annotation's element / selector / component chain / box, `Attached images: …` — twenty-odd lines of black bubble in which the developer's own note is one quoted fragment. Show the developer's words instead (the note, or one line per annotation sent, or the page-level message) and fold everything else behind a `▸ Capture · 2 images` pill that opens the full text in place. The words come from the server: the `user` event's first echo in a session gains an `intake` summary, set by the registry, so a reload, a reconnect and the session list all rebuild the same bubble. Nothing the agent receives changes. `docs/PRD-chat.md` §5.1, §5.3, F-119, N-28, N-30.

## Context
The chat panel is `packages/overlay/src/chat.ts`: `handle()` renders a `user` event through `userBubble(text, images)` (line ~680) as `.msg.user` with `white-space: pre-wrap` and a `📎 …` line for the image labels; the first `user` event of a session is the intake message. That message is built by `buildIntakeMessage` / `renderIntakeText` in `packages/server/src/intake-message.ts` from the capture bundle (page line, framework, console, network, `Developer's message: "…"` for a page-level chat (F-68), `Annotations (N):` with `n. [select|box|pin] "note"` blocks, `Attached images: …`), gets the F-14 paragraph appended for a quick note and, for `instructions: "first-message"` providers (F-51), the whole intake skill prepended under `# CRT intake instructions` and a `---` rule. The registry (`packages/server/src/sessions.ts`) builds it once per session in `firstMessage()` — from `start()` when a capture id is given, else from `attachCapture()` after a warm start — and already derives the F-30 one-liner there with `summarizeCapture(bundle)`. Every driver (`providers/claude.ts`, `codex.ts`, `acp.ts`, `antigravity.ts`, `stub.ts`) echoes what it was sent as `{ type: "user", text, images }`; the registry's `record()` numbers each event, stores it in `entry.events` and fans it out; `subscribe()` replays `entry.events` to a new SSE connection, so whatever `record()` stores is what a reloaded panel sees. The event types live in `packages/server/src/session-events.ts` (the overlay imports only the types). The F-8 label the popover header shows is `<Component> <tag.class>` (`ui.ts`, F-66 `title`). Tests: `test/intake-message.test.ts` (the message text and images), `test/sessions.test.ts` (rows at lines ~148, ~197, ~237 assert the `user` events of stub sessions; the stub runs in-process there), `e2e/chat.spec.ts` (lines 82–83, 130, 176, 282, 329–332, 387–388 read `.msg.user` text; `shadow(page, sel)` reaches into the overlay's Shadow DOM), `e2e/screenshots.spec.ts` (`chat.png` at 800 × 600 shows this bubble — PRD-polish F-116, so the PNG is regenerated here). Overlay pure logic is unit-tested from `packages/server/test` by importing `../../overlay/src/*` (e.g. `owner-stack.test.ts`, `accept-line.test.ts`). `dist/overlay.js` at 5fdcbd8 is 36.7 KB gzipped (N-3, N-30's +2 KB budget). `docs.test.ts` pins README sentences — change a pinned sentence and its test together (PRD-chat §12 rule 6).

## Ask
1. **Event contract** (`session-events.ts`): `export interface IntakeSummary { captureId: string; note: string | null; annotations: Array<{ n: number; kind: "select" | "box" | "pin"; note: string; label: string }>; quick: boolean; instructions: boolean }` and `intake?: IntakeSummary` on the `user` variant of `SessionEvent`, with the F-28 doc comment amended per PRD-chat §9 (the first echo of a session carries it; set by the registry, never by a driver).
2. **`summarizeIntake(bundle, opts: { quick: boolean; instructions: boolean }): IntakeSummary`** in `intake-message.ts`, exported, pure, beside `summarizeCapture`: `note` = the trimmed page-level note or null; one entry per annotation in bundle order with `note` trimmed (may be empty) and `label` = the F-8 label the popover header shows — the first component name (when any) and the element's `tag` + `#id` / `.class` short form for `select`, `box <w>×<h>` for a box, `pin` for a pin — reuse or lift the formatting the overlay uses so the two read the same; `quick` and `instructions` as passed. `buildIntakeMessage`, `renderIntakeText` and `prependInstructions` are not changed (N-28).
3. **Registry** (`sessions.ts`): `firstMessage()` computes the summary from the same bundle and keeps it on the entry (`entry.intake`), with `instructions` = whether it prepended them; `record()` attaches `{ ...event, intake }` to the **first** `user` event of the entry (a flag on the entry, cleared once used) and stores that decorated event, so the replay carries it; later `user` events are untouched. No driver file changes; the stub is untouched.
4. **Panel** (`chat.ts`): `fold(label: string, body: HTMLElement): HTMLElement` per PRD-chat §5.3 — `<button type="button" class="fold-pill" aria-expanded="false">▸ <label></button>` + `<div class="fold-body" hidden>`, click toggles `hidden`, `aria-expanded` and the glyph (`▸`/`▾`), no scroll, no focus change — and `userBubble(text, images, intake?)`: with `intake`, the body is the words per PRD-chat §5.1 (`note`; else one line per annotation: the note, or `#n · label` when the note is empty; `#n ` prefix on every line when more than one annotation), then the pill row `Capture` + ` · N image(s)` when `images.length` + ` · quick note` when `quick` + ` · with instructions` when `instructions`, and the fold body holding the `📎 …` image line (when any) and the full `text` in `white-space: pre-wrap`, 11 px monospace, `max-height: 40vh; overflow: auto`. Without `intake`, exactly today's bubble. `CHAT_CSS` gains the `.fold-pill` / `.fold-body` rows (white at 15 % alpha in `.msg.user`, ink at 6 % in `.msg.assistant` — the second is for M26 but the selector lands here so one component serves both; focus ring `ACCENT`, already imported). The `.imgs` line stays inside the fold body only when `intake` is present.
5. **Tests.** `test/intake-message.test.ts`: `summarizeIntake` rows — a page-level note; one select annotation with a note and a component (`label` = `CartSummary span.cart-total`); three annotations of the three kinds with the second note empty; `quick: true`; `instructions: true`; and a row that `buildIntakeMessage`'s `text` for the fixture is unchanged (pin its SHA-256, recorded in the Log — N-28). `test/sessions.test.ts`: the first `user` event of a stub session carries `intake` with the capture id, the notes and `quick: false` / `instructions: false`; a `first-message` variant session carries `instructions: true`; a quick note carries `quick: true`; the second `user` event (`write it`) has no `intake`; a second subscriber's replay carries it. `e2e/chat.spec.ts`: after Send the first `.msg.user` shows the note text and its `.fold-body` is hidden; the pill reads `Capture · 2 images`; click → `.fold-body` visible with `CRT intake for capture <id>` and `Attached images: viewport (annotated), annotation 1`; click → hidden; a page-level chat's bubble shows the developer's message (line ~387 row); a grouped send shows `#1 …` and `#2 …` (line ~329 row); an annotation sent without a note shows `#1 · <label>` (extend the fixture flow, PRD-chat §12 rule 4); after `page.reload()` the re-attached thread's bubble is folded with the same words (F-66). Rewrite the existing `.msg.user` assertions at lines 82–83, 282, 331–332, 387–388 to read `.fold-body` where they read the full text; never assert on the bubble's whole `textContent` (PRD-chat §11).
