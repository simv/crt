---
name: done
description: Close a CRT task from its reviewed pull request — mark it done as the last commit on the PR branch, then merge the PR — so closing never needs a second PR.
argument-hint: "<CRT-ID> [pr-url]"
disable-model-invocation: true
---

Close task `$0` (PRD F-40 as amended by PRD-chat F-122), from the project root `${CLAUDE_PROJECT_DIR}`. `crt` means `npx --no crt` if the project has it installed, else `npx -y claude-review-tool@0.7`. The done commit is the **last commit on the task's PR branch before the merge**: the flow is claim → build → commit → review → done → commit → merge, and closing a task never opens a second PR.

1. `crt task $0` (or read `.crt/tasks/$0-*.md`). The status must be `review`; otherwise say what it is and stop. Note the file name; `<slug>` is the file name without `CRT-NNNN-` and `.md`.
2. Find the task's pull request: `$1` if given, else `gh pr list --state open --head crt/$0-<slug> --json number,url,headRefName -q '.[0]'`, else `gh pr list --state open --search "$0 in:title" --json number,url,headRefName -q '.[0]'`. No open PR → look for a merged one (`--state merged`, same searches): found → this task was reviewed under the old flow, go to step 7; nothing at all (or no `gh`) → say so and stop; do not close the task.
3. Is it ready? `gh pr view <number> --json reviewDecision,statusCheckRollup,mergeable`. Stop and say why if `reviewDecision` is `CHANGES_REQUESTED`, if any check is failing or still running, or if `mergeable` is `CONFLICTING`. `APPROVED` or no review required is fine — the developer running this skill is the reviewer.
4. Get onto the PR branch with nothing of yours in the way: `git fetch origin`, then `git switch <headRefName>` and `git pull --ff-only`. If the project's hooks refuse to switch on a dirty tree, `git worktree add <sibling dir> <headRefName>` and work there. Other uncommitted changes belong to the developer: leave them alone; only the task file and the index are touched below.
5. In the task file set `status: done`, `updated: <now, ISO-8601 with offset>`, and append `- <YYYY-MM-DDTHH:MM+HH:MM> — done; closed in <PR URL>` to **## Log**. `crt task $0 --validate`, then `crt tasks` to regenerate `.crt/tasks/README.md`.
6. `git add .crt/tasks/$0-*.md .crt/tasks/README.md`, `git commit -m "chore(crt): close $0"`, `git push`. Then merge, as a bare command: `gh pr merge <number> --squash --delete-branch` (the project's merge method if `CLAUDE.md` names another). If the merge is refused — a ruleset, a check that has not finished, a required approval — stop there: the done commit is on the branch and the PR closes the task when it merges; put the exact merge command in your reply. After a merge: `git switch <default branch>` and `git pull --ff-only` (remove the worktree if you made one).
7. Old flow only (the PR merged before the task was closed): `git switch <default>` and `git pull --ff-only`; set `status: done` as in step 5 with `— done; merged in <PR URL>`; `crt task $0 --validate`, `crt tasks`; commit `chore(crt): close $0` and `git push`. If the push is rejected because the branch is protected, push it as `crt/$0-done` and `gh pr create --base <default> --title "chore(crt): close $0" --body "Marks $0 done; merged in <PR URL>."`; do not merge that PR yourself.
8. Report one line: the task ID, `done`, and the merged PR URL — or the branch the done commit is on and the merge command, or the URL of the close PR (step 7).
