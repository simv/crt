This document records what PRD-providers F-53 *assumed* against what the installed CLI *does*. Recordings: [`packages/server/test/providers/fixtures/codex/`](../../packages/server/test/providers/fixtures/codex/).

MCP probe: `probe/mcp-probe.mjs` — stdio MCP server that logs its environment and every JSON-RPC message to `$PROBE_LOG`, POSTs to the listener once at spawn (`spawn-ping`) and on every `tools/call` of its single tool `crt_ping`.

## 1. Flag acceptance

`codex exec --help` (0.154.0) lists `--json`, `-c`, `-i/--image <FILE>...`, `-m`, `-s/--sandbox`, `-C/--cd`, `--skip-git-repo-check`, `--ephemeral`, `--output-schema`, `-o`, `--approve-for-me`, `--dangerously-bypass-approvals-and-sandbox` — and **no** `--ask-for-approval`. `-a/--ask-for-approval <on-request|never>` exists only on the top-level `codex` command.

```

```

`codex exec resume --help` lists `--json`, `-c`, `-i/--image <FILE>` (single, repeatable), `-m`, `--last`, `--all`, `--skip-git-repo-check`, `--ephemeral`, `-o`, `--output-schema` — **no `--sandbox`, no `-C`**:


## Consequences for M9 (F-53 amendments, PRD-providers §12 rule 1 — flag names differ, capability exists)

1. **Turn 1**: `codex exec --json --sandbox read-only -C <projectRoot> -c approval_policy="never" -c mcp_servers.crt.default_tools_approval_mode="approve" [--image <png>]… -c mcp_servers.crt.command='<node>' -c mcp_servers.crt.args=['<cli.js>','mcp'] -c mcp_servers.crt.env={CRT_MCP_TOKEN='…',CRT_MCP_PORT='…'} [-m <model>] -c analytics.enabled=false -` — **not** `--ask-for-approval never`, and **`default_tools_approval_mode` is mandatory**: without it every `write_task` call fails with `MCP tool call requires approval, but approval policy is never`. Use TOML literal strings (`'…'`) for every path.
2. **Turn n**: `codex exec resume <threadId> --json -c approval_policy="never" -c mcp_servers.crt.default_tools_approval_mode="approve" -c sandbox_mode="read-only" [--image …]… -c mcp_servers.crt.* … -c analytics.enabled=false -` spawned with **`cwd: projectRoot`** — no `-C`, no `--sandbox`.
3. Resume assertion stays; only pass the UUID from `thread.started`.
4. `launchEnv: ["CODEX_THREAD_ID", "CODEX_SESSION_ID"]`; `telemetryOptOut: ["-c", "analytics.enabled=false"]`; skills dir `.agents/skills` (project) / `~/.codex/skills` (user).
5. **Events to map**: `item.started`/`item.completed` with `item.type` ∈ `mcp_tool_call` (`server`, `tool`, `arguments`, `result.content[]`, `error`, `status`), `command_execution` (`command`, `aggregated_output`, `exit_code`, `status`), `agent_message` (`text`, whole — no streaming), `error` (`message`; also used for non-fatal warnings such as unknown model metadata); `turn.completed.usage` → `result.detail`; `turn.failed.error.message` / top-level `error.message` → `error`. The F-53 "streamed if deltas are emitted" branch is dead on 0.154.0: emit `assistant_start`/`text`/`assistant_end` together per `agent_message`.
6. **Project location**: model commands cannot read a workspace under the %TEMP% short path; the fake-`codex` e2e scratch project must use a long path outside %TEMP%.
7. Stderr is noisy tracing output; the driver should surface only `error`/`turn.failed` JSONL messages, and keep stderr for `--verbose`/logs.
8. No sandbox fallback is needed: MCP servers run outside the command sandbox and reach `127.0.0.1`.
