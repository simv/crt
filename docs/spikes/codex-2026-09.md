## 1. Flag acceptance

`codex exec --help` (0.154.0) lists `--json`, `-c`, `-i/--image <FILE>...`, `-m`, `-s/--sandbox`, `-C/--cd`, `--skip-git-repo-check`, `--ephemeral`, `--output-schema`, `-o`, `--approve-for-me`, `--dangerously-bypass-approvals-and-sandbox` — and **no** `--ask-for-approval`. `-a/--ask-for-approval <on-request|never>` exists only on the top-level `codex` command.

```
> codex.exe exec --json --ask-for-approval never --skip-git-repo-check "say hi"
error: unexpected argument '--ask-for-approval' found
  tip: to pass '--ask-for-approval' as a value, use '-- --ask-for-approval'
< exit code=2
```

`codex exec resume --help` lists `--json`, `-c`, `-i/--image <FILE>` (single, repeatable), `-m`, `--last`, `--all`, `--skip-git-repo-check`, `--ephemeral`, `-o`, `--output-schema` — **no `--sandbox`, no `-C`**:

```
> codex.exe exec resume 01a0a4b1-… --json … --sandbox read-only -
error: unexpected argument '--sandbox' found                        (exit 2)
> codex.exe exec resume 01a0a4b1-… --json … -C C:\…\repo -
error: unexpected argument '-C' found                               (exit 2)
> codex.exe exec resume 01a0a4b1-… --json … -              (cwd = this repo, not the project)
Not inside a trusted directory and --skip-git-repo-check was not specified.   (exit 1, no JSONL)
```

`--strict-config` on `exec` validates `-c` keys before anything else (~50 ms): `approval_policy="never"`, `sandbox_mode="read-only"`, `analytics.enabled=false`, `otel.exporter="none"`, `otel.log_user_prompt=false`, `shell_environment_policy.inherit="all"`, and all `mcp_servers.crt.{command,args,env}` keys are recognised; `analytics.nope=false` → `Error loading config.toml: unknown configuration field \`analytics.nope\` in -c/--config override`, exit 1.

## 5. Environment, skills, telemetry

**Command sandbox on Windows.** `codex sandbox` runs a command under the same restricted-token sandbox model commands get. It requires a `[permissions.<name>]` profile:

```
> codex sandbox -c 'permissions.ro.sandbox_mode="read-only"' -P ro -C . -- node ../probe/envdump.mjs
env-count 97
codex-env {"CODEX_MANAGED_BY_NPM":"1","CODEX_MANAGED_PACKAGE_ROOT":"C:\\Users\\…\\npm\\node_modules\\@openai\\codex"}
ping 200 pong #2                                                 ← 127.0.0.1 reachable under read-only
```

The two `CODEX_MANAGED_*` variables are set by npm's `codex.js` wrapper (this invocation went through `codex.cmd`); a driver spawning `codex.exe` directly will not see them. Strings in `codex.exe` name `CODEX_SANDBOX` (`cli\src\doctor\network.rs`, seatbelt) and `CODEX_SANDBOX_NETWORK_DISABLED=1` (`core\src\spawn.rs`, network off only); neither appeared here. `launchEnv` for the Codex profile: **empty** on Windows; if Simon's model-run shell command (§2) prints a `CODEX_*` variable, use that.

**Skills.** `codex.exe` strings: `.codex`, `.codex/config.toml`, `.codex/agents`, `.codex/hooks`, `.agents`, `.agents/skills` (project-level markers, alongside `.git`), `$CODEX_HOME/skills` (user-level; skill-creator text: "create discoverable skills in `$CODEX_HOME/skills`, or `~/.codex/skills` when `CODEX_HOME` is unset"), `$CODEX_HOME/skills/.system` (bundled). `~/.codex/skills` exists on this machine and is empty. Skill format is Agent Skills (`SKILL.md` with YAML frontmatter, scripts/, references/).

**Telemetry.** Config tables `[analytics]` (`AnalyticsConfigToml`, one field: `enabled`) and `[otel]` (`exporter`, `trace_exporter`, `metrics_exporter`, `log_user_prompt`, `environment`, `span_attributes`, `tracestate`, `tool_result`). `-c analytics.enabled=false` passes `--strict-config`.

**Preflight.** `codex login status` → exit 0 / 1 maps cleanly to `loggedIn: true/false`, but true is not proof of a usable token. N-7's "not logged in" line must also be produced from `turn.failed` whose message matches `/log out and sign in again|Not logged in/`, with remediation `codex login`. `codex doctor --json` (schema `{schemaVersion, generatedAt, overallStatus, codexVersion, checks[]}`) does not detect the stale token either (`auth.credentials: ok`).

**Windows `[windows] sandbox = "elevated"`.** Present in Simon's config; `codex sandbox` worked without elevation prompts. Whether `exec --sandbox read-only` uses the elevated path for model commands: **Manual (Simon)**, observe the first real turn.

## Consequences for M9 (F-53 amendments, PRD-providers §12 rule 1 — flag names differ, capability exists)

1. **Turn 1**: `codex exec --json --sandbox read-only -C <projectRoot> -c approval_policy="never" [--image <png>]… -c mcp_servers.crt.command='<node>' -c mcp_servers.crt.args=['<cli.js>','mcp'] -c mcp_servers.crt.env={CRT_MCP_TOKEN='…',CRT_MCP_PORT='…'} [-m <model>] -c analytics.enabled=false -` — **not** `--ask-for-approval never`. Use TOML literal strings (`'…'`) for every path.
2. **Turn n**: `codex exec resume <threadId> --json -c approval_policy="never" -c sandbox_mode="read-only" [--image …]… -c mcp_servers.crt.* … -c analytics.enabled=false -` spawned with **`cwd: projectRoot`** — no `-C`, no `--sandbox`.
3. Resume assertion stays; only pass the UUID from `thread.started`.
4. `launchEnv: []`; `telemetryOptOut: ["-c", "analytics.enabled=false"]`; skills dir `.agents/skills` (project) / `~/.codex/skills` (user).
5. Stderr is noisy tracing output; the driver should surface only `error`/`turn.failed` JSONL messages, and keep stderr for `--verbose`/logs.
6. No sandbox fallback is needed: MCP servers run outside the command sandbox and reach `127.0.0.1`.
